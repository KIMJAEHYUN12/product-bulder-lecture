## 사용자 피드백 원문 요약

1. **"이전 추세선 방식이 더 좋았다"** — 최근 차트 개편(회귀채널+B/S마커)이 복잡해졌다
2. **"관심종목 개수 제한을 늘려달라"** — 일정 수 이상 추가 불가
3. **"NXT 차트 적용 가능한지"** — 시간외/야간 거래 차트 요청

|------|----------|

| 관심종목 | 서버 기준 **최대 20개** (메모리 문서의 5개는 ovision 구버전 기준, SimplyStock은 20개) |

## 주제 1: 이전 차트 방식 vs 현재 회귀채널

### 민수 (UX)
사용자가 "추세선 방식으로 되돌려달라"고 한 건 단순 향수가 아니라 **학습 비용 증가**의 신호다.
이전에 직관적인 추세선 2개만 보던 사용자가 갑자기 7선 + B/S마커 + 수급 히스토그램을 보면 당연히 혼란스럽다.

하지만 되돌리는 건 반대한다. 대신 **"간단 모드 / 상세 모드"** 이원화를 제안한다:
- 간단 모드(기본): 캔들 + 중심선 1개 + ±2σ 밴드 2개 = 총 3선. B/S 마커도 숨김.
- 상세 모드: 현재 그대로 (7선 + 마커 + 수급)

이미 3선/7선 토글이 있지만, B/S 마커와 수급 차트까지 포함한 **총체적 간단 모드**가 필요하다.

### 지현 (개발)
동의한다. 현재 3선/7선 토글은 이동평균선 개수만 바꾸는데, 사용자가 원하는 건 **전체적인 복잡도 조절**이다.

구현은 어렵지 않다. `StockChartV2`에 `viewMode: "simple" | "detail"` prop을 추가하고:
- simple: 단기 ±2σ 채널 + 중심선만. 장기채널 OFF, B/S OFF, 수급 차트 숨김
- detail: 현재 그대로

localStorage에 선택 저장하면 되니까 작업량은 1~2시간 수준이다.
**다만 되돌리기(rollback)는 절대 안 된다.** 새 기능을 원하는 사용자도 분명히 있을 것이다.

### 태호 (투자)
투자자 관점에서 회귀채널은 추세선보다 **통계적으로 우월하다**. 추세선은 고점-고점 또는 저점-저점을 수동으로 잇는 건데, 주관적이고 재현성이 없다.

문제는 **설명 부재**다. 사용자가 "이게 뭐냐"를 모르니까 복잡하게 느끼는 거다.
차트 첫 진입 시 2~3초짜리 **인트로 오버레이**("이 노란 밴드는 주가의 정상 범위입니다")를 보여주면 학습 곡선이 완화된다.

### 합의
- **되돌리기는 하지 않는다**
- **간단/상세 모드** 도입 (기본값: 간단)
- 첫 진입 시 짧은 설명 오버레이 추가 (1회성, localStorage 체크)
- 우선순위: **P1** (사용자가 이탈할 수 있는 직접적 불만)

## 주제 2: 관심종목 개수 제한

### 민수 (UX)
사용자가 "일정갯수 이상 넘어가면 추가가 안 된다"고 했는데, 서버는 20개 제한이다.
20개를 다 채웠을 때 **에러 메시지 없이 조용히 무시**되니까 "안 된다"고 인식한 것.
**피드백 부재**가 핵심 문제다. "관심종목은 최대 20개까지 가능합니다 (현재 18/20)" 같은 안내가 필요하다.

### 지현 (개발)
코드 확인 결과 서버(`functions/index.js` L2433)에서 `items.length >= 20`이면 조용히 무시한다.
프론트엔드에는 에러 핸들링이 없어서 사용자 입장에서는 버그로 보인다.

수정 방향:
1. 서버에서 제한 초과 시 `{ error: "MAX_REACHED", limit: 20 }` 반환
2. 프론트에서 토스트 표시: "관심종목은 최대 20개까지 추가할 수 있습니다"
3. 20개 → **30개**로 상향 (Firestore 문서 크기 문제없음, 배열 30개는 가벼움)

### 태호 (투자)
실제 매매자 기준으로 20개도 적다고 느낄 수 있다. 하지만 관심종목 100개 넣고 하나도 안 보는 사람이 대부분이다.
**20개면 충분하고, 30개는 여유**가 있다. 핵심은 개수보다 **갱신 빈도** — 1분마다 30종목 가격 업데이트하면 API 호출량이 늘어난다.

### 합의
- 서버 제한 20 → **30개**로 상향
- 제한 초과 시 **명확한 에러 메시지** 반환 + 프론트 토스트
- 현재 개수 표시: "관심종목 (12/30)"
- 우선순위: **P1** (구현 간단 + 사용자 직접 불만)

## 주제 3: NXT 차트 적용 가능 여부

### 민수 (UX)
NXT가 뭔지 명확히 해야 한다. 한국 주식시장에서 NXT는:
- **넥스트레이드(NXT)**: 2025년 출범한 대안거래소. 기존 KRX와 별도 마켓.
- 또는 단순히 **시간외 거래**(장전/장후)를 의미할 수도 있다.

사용자가 어떤 의미로 썼는지 확인이 필요하지만, 어느 쪽이든 "실시간 데이터"를 원하는 것이다.
현재 SimplyStock은 **정적 사이트(static export)** 기반이라 실시간 스트리밍과 구조적으로 맞지 않는다.

### 지현 (개발)
**기술적으로 매우 어렵다.**

1. **넥스트레이드(NXT) 데이터**: 공개 API가 없다. 증권사 HTS/MTS 전용 데이터이고, 일반 개발자가 접근할 수 있는 경로가 없다.

2. **시간외 거래 데이터**: KIS API로 이론상 가능하지만:
   - 장전(08:30~09:00), 장후(15:30~16:00) 체결가 조회 API가 별도로 있음
   - 하지만 **실시간 스트리밍이 필요**하고, Firebase Functions은 HTTP 요청-응답 구조라 WebSocket 상시 연결이 불가
   - Cloud Run에서 WebSocket 서버를 따로 띄우면 **월 비용이 크게 증가** (항상 인스턴스 유지)

3. **Yahoo Finance**: `postMarketPrice`, `preMarketPrice` 필드가 있지만 미국 주식만 해당. 한국 주식 시간외 데이터는 제공하지 않음.

**결론: 현실적으로 불가능하거나 비용 대비 효용이 낮다.**

### 태호 (투자)
솔직하게 말씀드리면, NXT/시간외 데이터는 **데이트레이더용**이다. SimplyStock의 핵심 가치는 "통계 기반 중장기 분석"이지 실시간 매매 도구가 아니다.

사용자에게 정중하게 설명하면 된다:
- "현재 SimplyStock은 일봉 기반 통계 분석에 집중하고 있어서, 실시간/시간외 데이터는 지원 계획에 없습니다"
- 대안: 증권사 MTS(키움, NH 등)와 병행 사용 권장

### 합의
- **NXT/시간외 차트는 구현하지 않는다** (비용, 기술 제약, 제품 방향성 불일치)
- 사용자에게 정중한 설명 + 대안 제시
- 우선순위: **보류** (구현 불가)

## 최종 우선순위 정리

| 순위 | 항목 | 작업량 | 사용자 체감 |
|------|------|--------|-----------|
| P1 | 간단/상세 모드 토글 (차트 복잡도 조절) | 중 (2~3시간) | 매우 높음 |
| P1 | 관심종목 에러 메시지 + 30개 상향 | 소 (1시간) | 높음 |
| P1 | 차트 첫 진입 인트로 오버레이 | 소 (1시간) | 중간 |
| 보류 | NXT/시간외 차트 | 불가 | - |
