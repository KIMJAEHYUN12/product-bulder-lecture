# SimplyStock 개선 설계 토론

> 작성일: 2026-03-09
> 참가자: 민수(UX), 지영(FE개발), 현우(콘텐츠기획)
> 목적: SimplyStock의 사용자 경험, 기능 구조, 콘텐츠 체계 개선 방향 도출

## 주제 1: 차트 마커 설명 — 차트 내에서 직접 이해할 수 있게

**민수(UX):** 가장 시급한 문제부터 짚겠다. 현재 차트에 초록/빨강 화살표와 박스가 나오는데, 사용자는 이게 뭔지 전혀 모른다. "이 초록색 화살표가 뭐예요?"라는 질문이 반복되는 상황이다. 가이드 페이지에 설명이 있지만, 차트를 보다가 가이드로 이동하는 사용자는 거의 없다. 차트 안에서 즉시 이해할 수 있어야 한다.

**지영(FE):** lightweight-charts의 마커 API를 정리하면, `createSeriesMarkers`로 마커를 찍을 때 `text` 프로퍼티가 있긴 한데 글자 수가 극히 제한적이다. 1~2글자 정도만 표시 가능하고, 툴팁 같은 건 마커 자체에는 없다. 현재 코드를 보면 `text: ""`으로 빈 문자열을 넣고 있다. 마커에 직접 설명을 달기는 어렵다.

**현우(콘텐츠):** 두 가지 레이어로 접근하면 된다. 첫째, 차트 바로 위나 아래에 "범례(legend)"를 상시 표시한다. 둘째, 마커를 클릭하거나 터치했을 때 하단에 해석 패널을 보여주는 방식이다.

**민수(UX):** 범례가 현실적이다. 현재 "상승 빨간점 / 하락 파란점" 범례가 있는데(StockChartV2.tsx 514~523행), 여기에 마커 범례를 추가하는 건 공간이 충분하다. 예를 들어:

```
■ 강화 매수 신호 (채널 하단 + 수급 유입 + 유리한 추세)
↑ 약화 매수 신호 (채널 하단 + 수급 유입 + 불리한 추세)
■ 강화 매도 신호 (채널 상단 + 수급 유출 + 유리한 추세)
↓ 약화 매도 신호 (채널 상단 + 수급 유출 + 불리한 추세)
```

**지영(FE):** 범례 방식이면 구현 부담이 적다. 다만 4줄 전부 보이면 모바일에서 공간을 많이 차지한다. 접기/펼치기로 처리하거나, "범례 보기" 아이콘 버튼을 만들어 토글하는 게 낫다.

**현우(콘텐츠):** 범례에 더해서, 크로스헤어로 마커 날짜에 멈추면 OHLCV 헤더 영역에 "매수 신호: 채널 하단 터치 + 외인 매수" 같은 한 줄 해설을 추가하면 좋겠다. 현재 크로스헤어 데이터 패널(574~595행)에 날짜와 가격 정보만 있는데, 그 날의 마커가 있으면 추가 텍스트를 보여주는 것이다.

**민수(UX):** 좋다. 크로스헤어 연동이면 사용자가 "이게 뭐지?" 하고 커서를 갖다 대는 자연스러운 동작에서 설명이 나오니까. 최초 방문 사용자를 위해 마커가 처음 나타나는 종목을 분석했을 때 한 번만 나오는 "마커 안내 배너"도 고려해볼 수 있다. localStorage로 "marker-intro-seen" 플래그를 저장하면 된다.

**지영(FE):** 크로스헤어 연동은 기술적으로 가능하다. `subscribeCrosshairMove` 콜백에서 현재 날짜를 받는데, 마커 데이터를 Map으로 만들어두면 O(1)으로 해당 날짜의 마커 정보를 찾을 수 있다. `buildMarkersV2` 함수가 이미 마커 배열을 반환하고 있으니, 여기에 상세 설명 필드(`description`)를 추가하면 된다.

**현우(콘텐츠):** 마커의 `text` 필드에 짧은 코드를 넣는 것도 방법이다. 예를 들어 "B" (Buy signal), "S" (Sell signal) 1글자만 넣어도 시각적으로 구분이 된다. lightweight-charts가 1~2글자는 허용하니까.

**민수(UX):** 좋은 아이디어다. 정리하면 3단계 해결:
1. 마커 `text`에 "B" 또는 "S" 표시 (최소 변경)
2. 차트 아래 접이식 범례 추가 (중간 변경)
3. 크로스헤어 날짜에 마커가 있으면 OHLCV 패널에 해설 텍스트 추가 (고급)

### 합의안: 차트 마커 설명

| 항목 | 내용 |
|------|------|
| 방안 A (즉시) | 마커 `text`에 "B"/"S" 1글자 표시. `buildMarkersV2`에서 `text: ""` → `text: "B"` 또는 `text: "S"` |
| 방안 B (단기) | 차트 컨트롤 영역에 접이식 마커 범례 추가. "?" 아이콘 클릭 시 4종 마커 설명 패널 토글 |
| 방안 C (중기) | 크로스헤어 OHLCV 패널에 마커 해설 연동. `MarkerV2` 타입에 `description` 필드 추가, 마커 Map 생성 후 크로스헤어 콜백에서 조회 |
| 방안 D (선택) | 최초 방문 시 마커 안내 배너 (localStorage 기반 1회 노출) |
| 수정 파일 | `src/lib/chartEngine.ts`, `src/components/StockChartV2.tsx` |

## 주제 2: 메인 페이지 개선

**현우(콘텐츠):** 현재 메인 페이지 진입 시, 종목을 검색하지 않은 상태에서 보이는 것이 "수급 반전 신호" 카드들과 "인기 종목" 버튼 3개, 핵심 기능 소개 4칸, 원자재 시세 티커다. 기능이 많아 보이긴 하는데, 사용자 동선이 불명확하다. "여기서 뭘 먼저 해야 하지?"라는 느낌이 든다.

**민수(UX):** 맞다. 신규 사용자와 재방문 사용자의 니즈가 완전히 다르다. 재방문 사용자는 검색창으로 바로 가서 종목을 치는데, 신규 사용자는 "이 서비스가 뭔데?"부터 시작한다. 현재는 둘 다를 위한 어중간한 페이지가 되어 있다.

**지영(FE):** 코드를 보면 `HomeDefault` 컴포넌트가 초기 상태를 담당하는데, 수급 반전 신호가 맨 위에 나온다. 이건 이미 서비스를 이해한 사용자에게는 좋지만, 처음 온 사용자는 "수급 반전 신호"가 뭔지도 모른다.

**민수(UX):** 제안하는 구조는 이렇다:

1. **검색바** (현재 위치 유지, 이건 잘 되어 있다)
2. **히어로 영역** (신규 사용자용): "주가의 정상 범위를 통계로 분석합니다" 같은 한 줄 + CTA 버튼 "삼성전자로 시작해보기" — 클릭하면 바로 삼성전자 차트가 로드
3. **수급 반전 신호** (재방문 사용자용): 현재와 동일하되 위치를 히어로 아래로
4. **핵심 기능 카드 4개**: 현재와 유사하되 가이드 링크 대신 직접 기능 사용으로 연결 (예: "수급 스캔" 카드 클릭 시 스캐너가 열리도록)

**현우(콘텐츠):** 히어로 영역에 대해, "삼성전자로 시작해보기" CTA는 훌륭하다. 가이드를 한 번도 안 읽은 사용자도 차트를 먼저 보면서 "이게 뭐지?"라는 호기심이 생기고, 그 다음에 가이드를 찾게 된다. 인기 종목 버튼 3개도 좋은데, 좀 더 눈에 띄게 크기를 키우면 좋겠다.

**지영(FE):** 히어로 영역은 `HomeDefault` 내에서 조건부로 보여줄 수 있다. localStorage에 "has-searched" 플래그가 없으면 히어로를 보여주고, 한 번이라도 종목 검색을 하면 히어로를 숨기는 식이다. 다만 이건 과한 최적화일 수 있으니, 그냥 항상 보여주되 컴팩트하게 만드는 게 낫다.

**민수(UX):** 동의한다. 히어로는 항상 보여주되 2~3줄로 매우 컴팩트하게. 현재 인기 종목 버튼이 `text-[10px]` 라벨에 `rounded-full`로 너무 작다. 이걸 카드 형태로 키우면 첫 화면의 행동 유도력이 크게 올라간다.

**현우(콘텐츠):** 기능 소개 카드 4개가 모두 가이드 링크로 연결되는데, 이건 좋지 않다. "회귀 채널 분석" 카드를 누르면 가이드 글이 나오는 게 아니라 "삼성전자의 회귀 채널"을 바로 보여줘야 한다. 또는 카드를 누르면 해당 기능의 간단 설명 + "직접 분석해보기" 버튼이 있는 작은 모달이 뜨는 방식도 있다.

**민수(UX):** 기능 카드의 링크 타겟을 바꾸는 건 좋은 방향이다. 다만 "회귀 채널 분석"이나 "수급 흐름"은 종목을 선택해야만 의미가 있으니, "삼성전자로 바로 보기"로 연결하고 하단에 "가이드 읽기" 텍스트 링크를 남기면 된다.

**지영(FE):** 추가로, `NewsTicker`가 헤더 바로 아래에 있는데 현재 금융 뉴스를 보여주고 있다. 이건 좋은 요소인데, 위치가 애매하다. 헤더에 통합하거나, 차트 아래로 내려서 "맥락 정보"로 쓰는 게 나을 수 있다.

**민수(UX):** 뉴스 티커는 현재 위치가 나쁘지 않다. 증권사 앱처럼 상단에 뉴스가 흐르는 건 익숙한 패턴이다. 건드리지 말자.

### 합의안: 메인 페이지 개선

| 항목 | 내용 |
|------|------|
| 히어로 영역 | 검색바 바로 아래에 2~3줄 짧은 소개 + "삼성전자 분석 시작" CTA 버튼. 언제나 노출 (컴팩트) |
| 인기 종목 | 3개 버튼을 카드 형태로 크기 확대. 종목명 + 현재가 + 등락률 표시 |
| 기능 카드 링크 | 가이드 페이지 대신 "삼성전자로 바로 보기" + 하단에 "가이드 읽기" 텍스트 링크 |
| 수급 반전 신호 | 현재 위치 유지 (히어로 아래) |
| 뉴스 티커 | 현재 위치 유지 |
| 수정 파일 | `src/components/home/HomeDefault.tsx`, `src/app/page.tsx` |

## 주제 3: 가이드/용어사전/분석자료실/소개 페이지 전면 개편

**현우(콘텐츠):** 현재 콘텐츠 구조를 정리하면:
- 가이드 10개 (회귀채널, 수급흐름, 매매동향, 수급스캔, 모의투자, 백테스트, PER밴드, 원자재, 투자성향, 실적캘린더)
- 용어사전 5개 (가치평가, 차트기본, 수급, 기술적분석, 주문유형)
- 분석자료실 3개 칼럼 + 가이드/용어사전 전체 재노출
- 소개 페이지 1개

문제점을 짚으면: 첫째, 가이드 10개 중 핵심 4개(회귀채널, 수급흐름, 매매동향, 수급스캔)와 보조 6개(모의투자, 백테스트 등)의 성격이 다른데 같은 레벨로 나열되어 있다. 둘째, 분석자료실이 가이드와 용어사전을 전부 포함하고 있어서 이 페이지의 정체성이 모호하다.

**민수(UX):** 가이드 10개가 너무 많다기보다는, 위계가 없는 게 문제다. 핵심 4개는 "SimplyStock의 고유 기능 설명"이고, 나머지 6개는 "부가 기능 사용법"이다. 이걸 구분해야 한다.

제안하는 구조:
- **핵심 가이드** (상단 강조): 회귀 채널, 수급 흐름, 매매동향, 수급 스캔
- **기능 가이드** (하단 그리드): 모의투자, 백테스트, PER밴드, 원자재, 투자성향, 실적캘린더
- **분석 칼럼** (별도 섹션): 현재 3개 + 추후 확장

**지영(FE):** 현재 `/guide/page.tsx`는 `guides` 배열을 순서대로 나열하고 있을 뿐이다. 배열을 두 그룹으로 나누면 바로 구현 가능하다. 코드 변경은 가이드 목록 페이지만 건드리면 된다.

**현우(콘텐츠):** 용어사전과 가이드의 중복 문제도 있다. 예를 들어 가이드의 "수급 흐름 읽는 법"과 용어사전의 "수급 용어 정리"가 겹치는 내용이 많다. 하지만 성격이 다르다 -- 가이드는 "어떻게 쓰느냐"이고, 용어사전은 "이게 뭐냐"다. 현재 구분이 잘 되어 있으므로 중복 제거보다는 상호 참조를 강화하는 게 좋다. 가이드 글 하단에 "관련 용어: 순매수, 프로그램매매" 같은 링크를 달면 된다.

**민수(UX):** 분석자료실(`/analysis/`) 페이지가 가이드와 용어사전을 전부 재노출하는 건 좋지 않다. 분석자료실은 "분석 칼럼"에 집중해야 한다. 현재 3개 칼럼만 있어서 빈약해 보이니까 가이드/용어사전을 끌어왔을 텐데, 차라리 칼럼이 적은 건 있는 그대로 보여주고 "매주 새 칼럼이 추가됩니다" 같은 안내를 넣는 게 낫다.

**지영(FE):** 분석자료실에서 가이드/용어사전 리스트를 제거하면 코드가 훨씬 가벼워진다. `analysis/page.tsx`에서 `guides` 배열과 `dicts` 배열을 빼면 된다.

**현우(콘텐츠):** 소개 페이지(`/about/`)는 현재 잘 되어 있다. 다만 "Ovision에서 SimplyStock이 독립 서비스로 전환되었다"는 맥락이 없다. 사실 사용자 입장에서는 이 맥락이 필요 없을 수 있다. Ovision 언급을 빼고 SimplyStock 자체 소개로 유지하면 된다. 현재 내용이 이미 그렇게 되어 있으므로 수정 불필요.

**민수(UX):** 변경사항/업데이트 공지 방법에 대해 -- changelog 페이지를 별도로 만드는 것보다는, 메인 페이지에 "최근 업데이트" 배너를 일시적으로 노출하는 게 효과적이다. localStorage에 마지막으로 본 버전을 저장하고, 새 버전이 있으면 배너를 보여주는 방식이다.

**지영(FE):** Ovision 프로젝트에서 `UpdateBanner` + `public/version.json` 패턴을 이미 사용하고 있다. SimplyStock에도 같은 패턴을 적용하면 된다. `version.json`에 `latestVersion`과 `message`를 넣고, 앱 로드 시 비교해서 배너를 띄우는 방식이다.

**현우(콘텐츠):** 추가로 가이드 목록 페이지에서 "차트 마커가 뭔가요?" 같은 FAQ 섹션을 하나 넣으면 좋겠다. 가이드를 글 전체 읽기 vs. 빠른 답변 찾기 두 동선을 모두 지원하는 것이다.

### 합의안: 콘텐츠 구조 개편

| 항목 | 내용 |

## 주제 4: 네비게이션 구조 개선

**민수(UX):** 현재 네비게이션을 정리하면:
- **사이드바 메뉴** (8개): 차트 분석, 밸류에이션, 종목 분석, 투자성향 테스트, 백테스트, 모의투자, 원자재 시세, 실적 캘린더
- **사이드바 하단 링크** (3개): 가이드, 용어사전, 분석자료실
- **푸터 링크** (7개): 가이드, 용어 사전, 분석 자료실, 원자재, 소개, 이용약관, 개인정보처리방침

문제: 8개 메뉴가 많다. 사용자가 주로 쓰는 건 "차트 분석"과 "밸류에이션" 정도다. 나머지 6개는 사용 빈도가 크게 떨어진다.

**지영(FE):** 코드를 보면 사이드바가 `sidebarOpen` state로 토글되는 서랍 형태다. 8개 메뉴 + 관심종목 + 하단링크가 한 서랍에 다 들어가 있다. 모바일에서 스크롤 없이 다 보이긴 하지만, 인지 부하가 크다.

**현우(콘텐츠):** 메뉴를 그룹화하면 된다:

```
[분석 도구]
  - 차트 분석 (메인)
  - 밸류에이션 (PER 밴드)
  - 종목 분석

[투자 연습]
  - 모의투자
  - 백테스트

[부가 도구]
  - 투자성향 테스트
  - 원자재 시세
  - 실적 캘린더

[학습]
  - 가이드
  - 용어사전
  - 분석자료실
```

**민수(UX):** 그룹 레이블을 넣으면 시각적으로 구분이 된다. 현재 사이드바에 "메뉴"라는 단일 그룹 레이블만 있는데(`text-[10px] font-medium uppercase tracking-wider`), 이걸 3~4개 그룹으로 나누면 훨씬 스캔하기 쉽다.

**지영(FE):** 구현은 간단하다. `<nav>` 안의 `<ul>`을 여러 개로 나누고 각각에 그룹 레이블을 넣으면 된다. 사이드바 폭 264px에 충분히 들어간다.

**민수(UX):** 하단 링크 3개(가이드, 용어사전, 분석자료실)가 사이드바에도 있고 푸터에도 있는 건 괜찮다. 사이드바에서는 "학습" 그룹으로 승격시키고, 푸터는 그대로 유지하면 된다.

**현우(콘텐츠):** 푸터의 7개 링크도 좀 많다. "가이드 | 용어 사전 | 분석 자료실 | 원자재 | 소개 | 이용약관 | 개인정보처리방침" 중에서 "원자재"는 이미 사이드바 메뉴에 있으니 푸터에서 빼도 된다.

**민수(UX):** 동의한다. 푸터는 법적 필수사항(이용약관, 개인정보처리방침) + 서비스 정보(소개) + 콘텐츠 허브(가이드, 분석자료실) 정도로 줄이자. 용어사전도 가이드 안에서 접근 가능하니까 빼도 무방하다.

**지영(FE):** 모바일 UX에서 한 가지 더. 현재 사이드바를 열려면 상단 햄버거 아이콘을 눌러야 하는데, 이건 표준적이긴 하지만 하단 탭바가 더 접근성이 좋다. 다만 하단 탭바를 추가하면 차트 영역이 줄어드는 트레이드오프가 있다.

**민수(UX):** 차트 분석 도구에서 하단 탭바는 비추천이다. 차트가 핵심인데 세로 공간을 빼앗기면 안 된다. 현재 햄버거 + 사이드바 조합을 유지하되, 사이드바 내부 구조만 개선하는 게 최선이다.

**현우(콘텐츠):** 데스크톱에서는 좌측에 관심종목 사이드바가 상시 보이는데, 여기에 간단한 네비게이션 아이콘(밸류에이션, 모의투자 등)을 추가하는 것도 고려할 수 있다. 하지만 관심종목의 공간이 빼앗기니까 보류하자.
