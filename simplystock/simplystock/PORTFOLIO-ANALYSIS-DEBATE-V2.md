# 재토론: "포트폴리오 사진 종합 분석" 기능 — 수정된 트래픽 전제

> 날짜: 2026-03-22
> 수정 사항: Referral 30%는 오비젼이 아닌 카카오톡 공유 등 외부 링크 유입. 오비젼 일평균 유입 3~4명으로 트래픽 기여 사실상 없음.

## Round 1: 트래픽 구조 재분석 — Referral의 정체

**최퍼널 (그로스):**
기존 토론에서 Referral 30%를 오비젼 유입으로 가정했는데, 이건 완전히 잘못된 전제였습니다. 오비젼 일평균 3~4명이면 월 100명도 안 됩니다. Referral 1,045명 중 오비젼 기여분은 3% 미만이에요.

그러면 나머지 97%는 어디서 왔는가? 카카오톡 공유가 주요 경로일 가능성이 높습니다. SimplyStock에는 카카오 공유 기능이 구현되어 있으니, 사용자들이 분석 결과를 공유하고, 그 링크를 타고 새 유저가 들어오는 구조입니다.

이건 매우 긍정적인 신호입니다. **유료 광고 없이 바이럴로 30%가 유입**되고 있다는 뜻이니까요.

**한비전 (프로덕트):**
동의합니다. 이 데이터를 재해석하면:

| 채널 | 비중 | 실제 의미 |
|------|------|-----------|
| Organic Search | 40% | SEO가 잘 작동 중 |
| Referral | 30% | 카카오톡/외부 링크 바이럴 |
| Direct | 20% | 재방문 (브랜드 인지) |
| Social | 10% | SNS 노출 |

오비젼은 이 구조에서 사실상 존재감이 없습니다. 이건 오히려 좋은 소식인데, **SimplyStock이 독립적으로 성장하고 있다**는 증거입니다. 오비젼에 의존하지 않는다는 게 확인됐으니 오비젼 처리 문제가 훨씬 단순해집니다.

**김애널 (금융):**
카카오톡 공유로 유입된다는 건, 사용자들이 "이거 봐봐"하면서 결과물을 공유한다는 뜻입니다. 주식 커뮤니티 특성상 **분석 결과의 공유성**이 핵심 성장 동력이라는 거죠. 포트폴리오 분석 기능을 만든다면, 이 공유 루프를 더 강화할 수 있습니다.

다만 주의할 점 — 포트폴리오 결과는 개인 보유 종목이 노출되므로, 공유 시 **민감 정보 마스킹 옵션**이 필요합니다. 종목명은 보여주되 수량/금액은 가릴 수 있어야 합니다.

## Round 2: 오비젼 처리 전략 재논의

**한비전 (프로덕트):**
기존 토론에서는 "오비젼 Referral이 크니까 301 리다이렉트 필수"라고 했는데, 일 3~4명이면 리다이렉트 효과도 미미합니다. 오비젼 처리 옵션을 다시 정리하면:

| 옵션 | 장점 | 단점 |
|------|------|------|
| A. 방치 | 비용 0, 리스크 0 | Firebase 무료 티어라 비용 없음 |
| B. 301 → SimplyStock | SEO 시그널 이전 (미미) | 설정 작업 필요 |
| C. 완전 폐쇄 | 깔끔 | 기존 3~4명 유실, API 서버 분리 필요 |

**정파이프 (기술):**
중요한 점 하나 — 오비젼의 Firebase Functions는 SimplyStock의 API 서버 역할을 합니다. `bitgak.co.kr/api/*`로 모든 API를 호출하고 있어요. 프론트엔드는 버려도 되지만 **Functions는 절대 끄면 안 됩니다**.

제 제안은 **옵션 A(방치)** 입니다. Firebase Hosting 무료 티어에서 돌아가고 있고, Functions는 어차피 유지해야 하고, 굳이 손댈 이유가 없습니다. 일 3~4명에 대해 리다이렉트 작업하는 건 ROI가 없어요.

**최퍼널 (그로스):**
동의합니다. 다만 한 가지만 추가하면 — 오비젼 도메인(`bitgak.co.kr`)에 SimplyStock으로 가는 배너 하나 정도는 넣어둘 수 있습니다. 5분 작업이고, 혹시 모를 유입도 챙길 수 있으니까요. 하지만 우선순위는 최하입니다.

**전원 합의: 오비젼은 방치(옵션 A). Functions만 유지. 신규 기능은 전부 SimplyStock에 집중.**

## Round 3: 카카오톡 바이럴과 포트폴리오 분석의 시너지

**최퍼널 (그로스):**
여기서 핵심 질문 — 카카오톡 공유가 이미 주요 성장 채널이라면, **포트폴리오 분석 기능이 이 바이럴 루프를 강화할 수 있는가?**

현재 공유되는 컨텐츠:
- 종목 분석 결과 (레이더 차트, 등급)
- 백테스트 결과
- 차트 게임 점수
- 투자 성향 퀴즈 결과

포트폴리오 분석이 추가되면:
- "내 포트폴리오 종합 진단 결과" 카드 공유
- 위험 분산도, 섹터 비중 시각화
- 종합 점수 (A~F 등급)

이건 공유 욕구가 매우 높은 컨텐츠입니다. "나 이번에 포폴 진단 받았는데 A등급 나왔어" — 이런 자랑성 공유가 자연스럽게 발생합니다.

**김애널 (금융):**
맞는데, 역방향도 있습니다. F등급 받은 사람은 공유 안 합니다. 그래서 **등급 체계를 너무 잔인하게 만들면 안 됩니다**. "위험 집중형 포트폴리오"처럼 중립적 표현을 쓰되, 시각적으로는 개선 가능성을 보여주는 방식이 좋습니다. 투자 조언이 아니라 **구조 분석**이니까요.

또 하나 — 이전 토론에서 확인한 법적 제약을 다시 강조합니다. "매수/매도/홀드" 같은 투자 조언은 절대 포함 불가. 순수하게 데이터 해석과 구조 분석만 제공해야 합니다.

**오모델 (AI/데이터):**
바이럴 관점에서 기술적으로 중요한 건 **공유 이미지 생성**입니다. 현재 SimplyStock에는 `analysisShareImage.ts`, `backtestShareImage.ts` 등 Canvas 기반 공유 이미지 생성 라이브러리가 이미 있습니다. 포트폴리오 분석도 같은 패턴으로 `portfolioShareImage.ts`를 만들면 됩니다.

공유 카드 구성 제안:

```
┌─────────────────────────────┐
│  SimplyStock 포트폴리오 진단  │
│                             │
│  [섹터 분포 도넛차트]         │
│                             │
│  보유 종목: 8개              │
│  섹터 분산: ★★★★☆           │
│  변동성: 중간                │
│                             │
│  종합 유형: 성장 집중형       │
│  simplystock.co.kr          │
└─────────────────────────────┘
```

등급(A~F)보다 **유형 분류**가 공유에 더 적합합니다. "성장 집중형", "안정 배당형", "모멘텀 추격형" — 이런 라벨은 자기 정체성과 연결되어 공유 동기가 강합니다.

**한비전 (프로덕트):**
완전 동의. 투자 성향 퀴즈가 공유율 높은 이유도 "나는 어떤 유형인가"에 대한 호기심이잖아요. 포트폴리오 유형도 같은 심리를 자극합니다.

바이럴 퍼널을 정리하면:

```
[기존 유저] → 포폴 사진 업로드 → 진단 결과
    ↓
카카오톡 공유 (유형 카드)
    ↓
[새 유저] → "나도 해볼까?" → 사이트 방문
    ↓
포폴 업로드 → 진단 → 또 공유
    ↓
(바이럴 루프)
```

이 루프가 기존 Referral 30% 채널과 완벽하게 맞물립니다.

## Round 4: 포트폴리오 분석을 SimplyStock에 넣을 때의 UX 흐름

**한비전 (프로덕트):**
기존 토론에서 SimplyStock 배치에 대해 논의했는데, 카카오톡 바이럴 전제가 바뀌었으니 UX도 재설계합니다.

카카오톡에서 유입되는 유저의 특성:
1. 지인이 공유한 링크를 클릭
2. 결과 페이지를 먼저 봄 (공유된 카드)
3. "나도 해볼까?" 동기 발생
4. 최소한의 단계로 자기 진단 시작

따라서 **공유 링크 → 결과 미리보기 → CTA "내 포트폴리오도 진단하기"** 흐름이 핵심입니다.

```
[카카오톡 링크 클릭]
    ↓
/portfolio/result?id=xxx (공유된 결과 페이지)
    ↓
"내 포트폴리오도 진단받기" 버튼
    ↓
/portfolio (업로드 페이지)
    ↓
사진 업로드 → 실시간 수집 → 결과
    ↓
공유 버튼 → 카카오톡
```

**정파이프 (기술):**
Static export(`output: 'export'`)에서 동적 결과 페이지를 어떻게 처리할지가 관건입니다. 두 가지 방법:

1. **클라이언트 사이드 렌더링**: `/portfolio/result` 페이지에서 query param으로 ID 받아 Firestore에서 로드
2. **OG 이미지 별도 처리**: 카카오톡 미리보기용 OG 이미지는 Functions에서 동적 생성

Static export라 서버 사이드 OG 태그는 불가하지만, 카카오톡 공유 시 `Kakao.Link.sendDefault`로 이미지와 설명을 직접 지정하므로 OG 메타태그 의존도가 낮습니다. 기존 `kakaoShare.ts` 패턴 그대로 쓰면 됩니다.

**오모델 (AI/데이터):**
결과 저장 구조도 정리하면:

```
Firestore: portfolio_analyses/{id}
├── userId (optional, 비로그인 가능)
├── createdAt
├── holdings: [{code, name, qty, avgPrice, currentPrice, ...}]
├── analysis: {
│   ├── sectorDistribution: {IT: 40%, 금융: 20%, ...}
│   ├── volatilityScore: 65
│   ├── diversificationScore: 72
│   ├── portfolioType: "성장 집중형"
│   └── insights: ["IT 섹터 비중 40%로, 업종 편중도가 높은 구조입니다", ...]
│ }
├── dataSnapshots: {  // 수집된 실데이터 스냅샷
│   ├── perBands: {...}
│   ├── investorTrends: {...}
│   └── charts: {...}
│ }
└── shareImageUrl (optional)
```

비로그인 사용자도 이용 가능하게 하되, 결과 저장 기간을 7일로 제한합니다. 로그인 유저는 히스토리 누적.

## Round 5: 데이터 파이프라인 — 실데이터의 차별화

**오모델 (AI/데이터):**
이전 토론의 핵심은 그대로 유효합니다 — **ChatGPT와의 차별화는 실시간 실데이터 수집 과정을 보여주는 것**. 카카오톡 바이럴 전제가 바뀌어도 이 부분은 변하지 않습니다.

다만 바이럴 맥락에서 강조할 점이 추가됩니다: 카카오톡으로 들어온 신규 유저는 "빨리 결과를 보고 싶은" 상태입니다. Theatre Effect(실시간 수집 과정 보여주기)가 너무 길면 이탈합니다.

제안하는 타임라인:

| 단계 | 시간 | 표시 내용 |
|------|------|-----------|
| OCR 인식 | 2~3초 | "포트폴리오 인식 중... 8개 종목 발견" |
| 데이터 수집 | 5~8초 | "삼성전자 시세 수집... 수급 분석..." (프로그레스 바) |
| AI 분석 | 3~5초 | "종합 진단 작성 중..." |
| 결과 | 즉시 | 전체 결과 + 공유 버튼 |

**총 10~16초**가 적정입니다. 기존 빗각 분석이 SSE로 20초+ 걸리는데, 포트폴리오는 병렬 수집으로 단축해야 합니다.

**정파이프 (기술):**
병렬 수집 아키텍처:

```javascript
// 8개 종목 동시 수집
const holdings = ['005930', '000660', ...];
const results = await Promise.all(
  holdings.map(code => Promise.all([
    fetchPerBand(code),      // PER/PBR
    fetchInvestorTrend(code), // 수급
    fetchStockChart(code),    // 차트
  ]))
);
```

기존 API가 전부 있으니 새로 만들 건 **오케스트레이션 엔드포인트** 하나입니다:
- `/api/portfolio-analyze` — OCR → 종목 코드 매칭 → 병렬 수집 → Gemini 해석 → 결과 반환

SSE로 진행 상황을 스트리밍하면 Theatre Effect도 자연스럽게 구현됩니다.

## Round 6: 수익화와 프리미엄 전략

**최퍼널 (그로스):**
카카오톡 바이럴이 주요 성장 채널이라는 점을 감안한 수익화 전략:

**무료 제공 (바이럴 극대화):**
- 포트폴리오 사진 인식 + 기본 진단 (섹터 분포, 종목 수, 포트폴리오 유형)
- 공유 카드 생성
- 월 3회 제한

**프리미엄 (유료/광고 시청):**
- 상세 분석 (종목별 PER 밴드 위치, 수급 현황, 변동성 분석)
- 히스토리 비교 (이전 진단 대비 변화)
- 무제한 진단

광고 모델이 더 현실적입니다. 리워드 광고(30초 시청 → 상세 분석 1회)는 주식 앱에서 거부감이 낮습니다. 현재 AdSense가 이미 붙어있으니 인터스티셜 광고를 결과 페이지 앞에 넣을 수 있습니다.

**김애널 (금융):**
프리미엄 경계를 어디에 둘지가 중요합니다. **기본 진단은 무조건 공유 가능**해야 바이럴이 살아요. 프리미엄은 "더 깊이 보기"에 해당하는 부분만. 공유 카드에는 프리미엄 마크를 넣지 마세요 — 공유받은 사람이 "유료구나" 하고 이탈합니다.

## Round 7: 법적 가이드라인 재확인

**김애널 (금융):**
이전 토론에서 확립한 원칙을 반드시 유지합니다:

### 절대 금지 표현
- 매수/매도/홀드/추천/비추
- "~해야 합니다", "~하는 게 좋습니다" (행동 지시)
- 목표가, 적정가 제시
- "저평가/고평가" 단정

### 허용 표현
- "IT 섹터 비중이 40%로, 업종 편중도가 높은 구조입니다"
